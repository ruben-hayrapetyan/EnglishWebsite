# tools/textbook: the textbook converter

Turns the textbook's source files into the site's pages:

- `index.html`: the site's front page, which is the textbook's contents page, with every chapter grouped by unit.
- `chapter-<id>.html`: one reading page per chapter that has a source.
- `assets/img/chapter-<id>-<figure>.png|jpg`: the chapter figures.

Every generated file has a "Generated by tools/textbook" comment. **Don't edit generated files by hand.** Change the source or `textbook/textbook.json`, then rebuild.

## Run it

```sh
.venv/bin/python -m tools.textbook build            # convert and write the pages
.venv/bin/python -m tools.textbook build --check    # change nothing; exit 1 if pages are stale (CI runs this)
.venv/bin/python -m tools.textbook build --strict   # also fail on warnings, e.g. missing alt text
.venv/bin/python -m tools.textbook inspect FILE     # list the headings the converter sees in a source
```

Setup is in the main README, under "Run the tests".

## Add or update a chapter

**The usual way: the website.** Open `upload.html` ("Add a chapter" in the footer). Pick the chapter, or "the whole book", choose the PDF or Word file, and paste a GitHub token. The page opens a pull request. The **Convert uploads** workflow (`.github/workflows/convert.yml`) converts it on that pull request, commits the generated pages, runs the tests and comments with any warnings. Merge it to publish.

**Without the page:** upload the file on GitHub into `textbook/sources/` on a new branch and open a pull request. The same workflow converts it.

Files are matched to chapters **by name**, so nobody has to edit `textbook.json` to add a source:

| File in `textbook/sources/` | Becomes |
|---|---|
| `<chapter id>.pdf`, `.docx` or `.md` | That chapter, e.g. `neuronal-activity.pdf` |
| `book.pdf`, `.docx` or `.md` | The whole book. Each chapter without its own file is cut out where the book names it: a bold or larger line such as "Chapter 7: Neuronal activity", "Chapter X: Chronotypes", "UNIT AND CHAPTER: …" or just the title. Contents pages and bullets are skipped. Each chapter is then converted on its own, so authors' different fonts don't confuse each other. A chapter that isn't found stays "Coming soon", with a warning. (A Word or Markdown book is split by its headings.) |

Two files for one chapter (say `chronotypes.pdf` and `chronotypes.docx`) is an error; the upload page removes the old one for you.

**By hand, for special cases:** set `source` in `textbook/textbook.json`, which always wins over file names. Then run `build` and commit the source, the JSON and the generated files together.

The source can take three shapes:

| Shape | `source` |
|---|---|
| One file per chapter | `"sources/chronotypes.docx"` |
| A combined book, picked out by heading | `{"file": "sources/book.pdf", "heading": "Chapter 5: Chronotypes"}` |
| A combined PDF, picked out by pages | `{"file": "sources/book.pdf", "pages": "41-58"}` |

Run `inspect` on a combined book to see the exact heading text to use.

### Chapter fields

| Field | Required | What it does |
|---|---|---|
| `id` | yes | Permanent slug. It becomes `chapter-<id>.html`, and `study-<id>.html` for a study kit. **Never change it once published.** Readers' notes are saved against the page address. |
| `title`, `unit`, `authors` | yes | Shown on the page and the contents page. `authors` holds slugs from the top-level `authors` map. |
| `source` | no | Leave it out and the chapter shows as "Coming soon". |
| `summary` | no | One-sentence lede under the title. |
| `highlight` | no | The words of the title that get the highlighter. |
| `ai_credit` | no | The authors' own statement about generative AI in the chapter, e.g. "Figures 2 and 3 were plotted with code written by Claude (Anthropic)." It's added to the page's AI credit. |
| `figures` | no | Alt text per figure, e.g. `{"figure-1": {"alt": "..."}}`. Use this when the source has none. |
| `outline` | no | Section names, shown on the author pages until the source is converted. Write names, or `{"section": "Name", "subsections": [...]}` to nest. |

## Pages that describe the book

Some hand-written pages also describe the book: the study hub (`study.html`), the author pages (`author-*.html`) and the team page (`teams.html`). Those parts are never typed out by hand. Each one is a marked region that the build fills in from `textbook.json` and the converted chapters:

```html
<!-- textbook:author-chapters daniel -->
...generated...
<!-- /textbook -->
```

Only the text between the markers changes. The rest of the page stays its author's. `build --check` fails if a region is out of date, just like a chapter page.

| Region | What it shows |
|---|---|
| `count authors`, `count chapters`, `count units` | A number from `textbook.json`, inline |
| `study-cards <unit id>` | A unit's chapters on the study hub. A chapter shows "Ready", with its slide and question counts, as soon as `study-<id>.html` exists. |
| `author-chapters <author slug>` | An author's chapter cards: unit, title, coauthors, a link to the chapter once it's converted, and its section outline |

Section outlines come from the chapter's real headings once its source is converted, whatever the format. Until then they come from the chapter's `outline` in `textbook.json`. So nothing on these pages depends on one particular PDF: swap the source, rebuild, and every page follows.

## Only the written content, the same shape for every chapter

The class wrote each chapter to a template: UNIT AND CHAPTER, CONTRIBUTORS, LEARNING OBJECTIVES, CHAPTER OUTLINE, then CHAPTER WRITTEN CONTENT, then CHAPTER ADD-INS, GLOSSARY and REFERENCES. When a chapter uses the template, the site shows **only its written content** (`sections.py`):

- **Where it starts:** a "CHAPTER WRITTEN CONTENT" label, including variants like "(Ben)" or "- John Liu".
- **What stops it:** front-matter labels (contributors, objectives, outline, "Sections:") and end labels (add-ins, glossary, vocab, references, works cited, citations).
- **Chapters by several authors** keep each author's written part, in order.
- **A learning-objectives list placed inside the text** is skipped, and the text resumes at the next heading.
- **A chapter with no "written content" label** starts at the first heading followed by real paragraphs.
- **A chapter that doesn't use the template** is left whole, even if it has a "References" heading.

Then every chapter gets the same structure (`structure.py`):

- Short bold lines and one-item bold lists ("1. What is being measured?") become headings.
- A heading that wrapped onto a second line is joined back together.
- An opening heading that restates the chapter title is removed.
- Each author's part is levelled on its own: its top headings are h2 and the next level h3. Numbered headings ("1.", "2.", "2.1") take their level from their numbers, and no level is skipped.

A whole-book PDF written to the template is split where each chapter's opening block ("UNIT AND CHAPTER" or "CONTRIBUTORS") starts, which is more reliable than its title line.

## Supported formats

| Format | How it's read |
|---|---|
| **PDF** (from Word, Google Docs, LaTeX, Pages...) | Structure is rebuilt from layout. Headings come from font size, or short bold lines. The reader also handles:<br>• running heads and page numbers, even when they alternate between left and right pages or carry the page number<br>• repeated logos, and the source's own table of contents (the site builds its own)<br>• words split across lines (rejoined) and paths broken after a slash<br>• paragraphs that continue across page breaks, column breaks or a figure placed mid-sentence<br>• two-column pages, read left column first<br>• bullets and section numbers written as separate text from their words<br>• lists, including numbered items that run over a page with different margins<br>• monospace lines, which become code blocks<br>• captions ("Figure N", "Fig. N", "Table N") and tables, with or without ruled borders<br>• figures drawn as vector paths (for example matplotlib exports), rendered to PNG<br>• footnotes, collected into a Notes section |
| **Word .docx** (also what Google Docs, Pages and LibreOffice export) | Heading styles, list numbering (including nesting), image alt text, the Caption style, tables, links, quotes and code are read directly. |
| **Markdown** (.md) | CommonMark plus tables. Images are PNG or JPEG files next to the Markdown file. Raw HTML is dropped, never passed through. |

Anything else (.doc, .odt, .pages, .tex, .html) gets an error that says how to export it to a supported format.

### Known limits

- **Scanned PDFs** (pictures of text) are rejected. Run OCR first, or export the original document. A few picture-only pages inside an otherwise normal PDF, such as photos of handwritten notes, are kept as figures; describe them with `figures` alt text.
- **Transparent images**, such as equations from Google Docs, are flattened onto white, so they stay readable in every theme.
- **Equations** are kept as plain text, with a warning naming the pages. Check them by hand.
- **PDFs carry no alt text.** Figures from a PDF get their caption as alt text, with a warning, until you add `figures` alt text in `textbook.json`.
- **Word footnotes** aren't converted yet; you get a warning.
- **Unusual tables** (merged cells, a borderless table on a two-column page) may come out as plain text. A "Table N" caption with no table found gives a warning.

## How it's built

```
source file ──reader──▶ Document (model.py) ──structure.py──▶ chapter body ──render.py──▶ HTML
             pdf.py / docx.py / markdown.py      pick section, drop title,    template head, layout A,
                                                 renumber headings            chapter-nav, AI credit
```

- Every reader produces the same `Document` model, so adding a format means adding a reader and one line in `readers/__init__.py`.
- Pages copy their `<head>`, skip link, header and footer from `_template.html`. Template changes reach every chapter on the next build.
- Output is deterministic. Each paragraph sits on one line of normalized text: NFC, no ligatures or soft hyphens. The notes feature finds highlights by their exact text.
- Author names link to `author-<slug>.html`, and a "Practice with the study kit" button links to `study-<id>.html`, but only when those pages exist. The next build adds the links once they do.

## Tests

Tests are in `tests/textbook/`:

| Kind | Files |
|---|---|
| Glass-box units | `test_normalize.py`, `test_pdf_layout.py` (each layout heuristic on hand-built lines), `test_structure.py`, `test_render.py`, `test_manifest.py` |
| Black-box | `test_readers.py` (real PDF, .docx and .md files written by `samples.py`, including `real_world_pdf`, which rebuilds the quirks found in real books), `test_cross_format.py` (the same chapter in all three formats must give the same outline), `test_build.py` (build, CLI, determinism, cleanup) |
| Contracts | `test_generated_pages.py` (site rules and notes and read-aloud needs on real output), `test_repo_textbook.py` (committed pages are fresh; study kits and author pages match `textbook.json`) |
| End to end | `test_e2e_chapters.py` (a reader clicking through the contents and chapters in Chromium: both themes, 390px and 1440px, keyboard, JavaScript off, axe) |

CI requires at least 85% branch coverage of `tools/`.
