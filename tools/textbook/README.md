# tools/textbook: the textbook converter

Turns the textbook's source files into the site's pages:

- `textbook.html`: the contents page, with every chapter grouped by unit.
- `chapter-<id>.html`: one reading page per chapter that has a source.
- `assets/img/chapter-<id>-<figure>.png|jpg`: the chapter figures.

Every generated file has a "Generated by tools/textbook" comment. **Don't edit generated files by hand.** Change the source or `textbook/textbook.json`, then rebuild.

## Run it

```sh
.venv/bin/python -m tools.textbook build            # convert and write the pages
.venv/bin/python -m tools.textbook build --check    # change nothing; exit 1 if pages are stale (CI runs this)
.venv/bin/python -m tools.textbook build --strict   # also fail on warnings, e.g. missing alt text
.venv/bin/python -m tools.textbook inspect FILE     # list the headings the converter sees in a source
```

Setup is in the main README, under "Run the tests".

## Add or update a chapter

1. Put the source file in `textbook/sources/`.
2. Point the chapter at it in `textbook/textbook.json`:

   ```json
   { "id": "neuronal-activity", "title": "Neuronal activity: spikes and local field potentials",
     "unit": "ultradian", "authors": ["daniel"],
     "source": "sources/neuronal-activity.pdf" }
   ```

3. Run `build`. Read the warnings, fix what they point at, then commit the source, the JSON and the generated files together.

The source can take three shapes:

| Shape | `source` |
|---|---|
| One file per chapter | `"sources/chronotypes.docx"` |
| A combined book, picked out by heading | `{"file": "sources/book.pdf", "heading": "Chapter 5: Chronotypes"}` |
| A combined PDF, picked out by pages | `{"file": "sources/book.pdf", "pages": "41-58"}` |

Run `inspect` on a combined book to see the exact heading text to use.

### Chapter fields

| Field | Required | What it does |
|---|---|---|
| `id` | yes | Permanent slug. It becomes `chapter-<id>.html`, and `study-<id>.html` for a study kit. **Never change it once published.** Readers' notes are saved against the page address. |
| `title`, `unit`, `authors` | yes | Shown on the page and the contents page. `authors` holds slugs from the top-level `authors` map. |
| `source` | no | Leave it out and the chapter shows as "Coming soon". |
| `summary` | no | One-sentence lede under the title. |
| `highlight` | no | The words of the title that get the highlighter. |
| `ai_credit` | no | The authors' own statement about generative AI in the chapter, e.g. "Figures 2 and 3 were plotted with code written by Claude (Anthropic)." It's added to the page's AI credit. |
| `figures` | no | Alt text per figure, e.g. `{"figure-1": {"alt": "..."}}`. Use this when the source has none. |

## Supported formats

| Format | How it's read |
|---|---|
| **PDF** (from Word, Google Docs, LaTeX, Pages...) | Structure is rebuilt from layout. Headings come from font size, or short bold lines. Running heads, page numbers and repeated logos are dropped. Words split across lines are rejoined. Paragraphs continue across page and column breaks. Two-column pages read left column first. Lists are found by bullets and numbers, captions by "Figure N", "Fig. N" or "Table N". Bordered tables become HTML tables. Figures drawn as vector paths (for example matplotlib exports) are rendered to PNG. Footnotes become a Notes section. |
| **Word .docx** (also what Google Docs, Pages and LibreOffice export) | Heading styles, list numbering (including nesting), image alt text, the Caption style, tables, links, quotes and code are read directly. |
| **Markdown** (.md) | CommonMark plus tables. Images are PNG or JPEG files next to the Markdown file. Raw HTML is dropped, never passed through. |

Anything else (.doc, .odt, .pages, .tex, .html) gets an error that says how to export it to a supported format.

### Known limits

- **Scanned PDFs** (pictures of text) are rejected. Run OCR first, or export the original document.
- **Equations** are kept as plain text, with a warning naming the pages. Check them by hand.
- **PDFs carry no alt text.** Figures from a PDF get their caption as alt text, with a warning, until you add `figures` alt text in `textbook.json`.
- **Word footnotes** aren't converted yet; you get a warning.

## How it's built

```
source file ──reader──▶ Document (model.py) ──structure.py──▶ chapter body ──render.py──▶ HTML
             pdf.py / docx.py / markdown.py      pick section, drop title,    template head, layout A,
                                                 renumber headings            chapter-nav, AI credit
```

- Every reader produces the same `Document` model, so adding a format means adding a reader and one line in `readers/__init__.py`.
- Pages copy their `<head>`, skip link, header and footer from `_template.html`. Template changes reach every chapter on the next build.
- Output is deterministic. Each paragraph sits on one line of normalized text: NFC, no ligatures or soft hyphens. The notes feature finds highlights by their exact text.
- Author names link to `author-<slug>.html`, and a "Practice with the study kit" button links to `study-<id>.html`, but only when those pages exist. The next build adds the links once they do.

## Tests

Tests are in `tests/textbook/`:

| Kind | Files |
|---|---|
| Glass-box units | `test_normalize.py`, `test_pdf_layout.py` (each layout heuristic on hand-built lines), `test_structure.py`, `test_render.py`, `test_manifest.py` |
| Black-box | `test_readers.py` (real PDF, .docx and .md files written by `samples.py`), `test_cross_format.py` (the same chapter in all three formats must give the same outline), `test_build.py` (build, CLI, determinism, cleanup) |
| Contracts | `test_generated_pages.py` (site rules and notes and read-aloud needs on real output), `test_repo_textbook.py` (committed pages are fresh; study kits and author pages match `textbook.json`) |
| End to end | `test_e2e_chapters.py` (a reader clicking through the contents and chapters in Chromium: both themes, 390px and 1440px, keyboard, JavaScript off, axe) |

CI requires at least 85% branch coverage of `tools/`.
